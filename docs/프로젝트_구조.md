# gunpolaw — 프로젝트 구조 & 주요 함수 시그니처

군포시 자치법규(조례·규칙)가 인용한 **상위 법령 조항이 조례 시행 이후 개정됐는지**를
조문 단위로 자동 점검·권고하는 도구. **Python 3 표준 라이브러리만** 사용(외부 의존성 0),
저장소는 **단일 SQLite**(`gunpolaw.db`). "배치 1회 수집·분석 → 이후엔 DB만 서빙".

```
gunpolaw/
├─ __main__.py   CLI 진입(플래그 디스패치)
├─ config.py     대상 지자체 설정(환경변수/region.json)
├─ moleg.py      법제처 OpenAPI 클라이언트(유일한 라이브 호출 지점)
├─ parse.py      법령/조례 XML → 구조화 파싱
├─ clauses.py    조문 라벨(제N조의M) 토큰화·정규화
├─ extract.py    조례 본문 → 상위법 인용 추출
├─ history.py    법령 시행일자별 버전 목록·시점 본문 조회
├─ checks.py     인용 조항 개정 여부 판정(등급 산출) ★엔진 핵심
├─ pipeline.py   조례 1건 분석 오케스트레이션(수집→추출→판정)
├─ reparse.py    DB-only 재분석(라이브 API 0) + 증분 소스
├─ batch.py      전수 수집·적재·개정 델타 감지·역추적·공유 export
├─ db.py         SQLite 스키마·커넥션
├─ report.py     권고서 렌더 모델 → HTML/CSV
├─ serve.py      대시보드 HTTP 서버 + 정적 사이트 생성
└─ diag.py       /admin 판정 근거 검사(진단)
```

데이터 흐름: `moleg`(수집) → `parse`/`extract`(구조화) → `history`(시점본) →
`checks`(판정) → `pipeline`(조립) → `batch`(적재) → `report`/`serve`(표출).
재분석은 `reparse`가 DB의 `body_xml`만으로 `pipeline`을 다시 돌림(API 0).

## CLI (`__main__.py`)

| 명령 | 설명 | OC키 |
|---|---|---|
| `--batch [N] [--deep] [--incr\|--max-age D]` | 전수 수집·분석(N=건수제한, deep=내용diff 확정, incr=무한재사용, max-age=신선도) | 필요 |
| `<MST> [--deep]` | 조례 1건 분석 | 필요 |
| `--reparse` | 영속 body_xml로 전건 재파싱(라이브 API 0) | 불요 |
| `--report` | 저장 findings 집계 | 불요 |
| `--changes [--all]` | 법령 개정 → 영향 조례 역추적(미검토만/전체) | 불요 |
| `--ack <law_id> [key]` / `--unack` | 개정 검토완료 표시/해제 | 불요 |
| `--recommend [경로]` / `--recommend --mst <MST>` | 권고서 HTML(전체/1건) | 불요¹ |
| `--serve [포트]` | 대시보드 서빙(기본 8765, 읽기전용) | 불요 |
| `--export-share [zip]` | 공유용 올인원 zip(코드+슬림DB+안내문) | 불요 |
| `--export-static [폴더]` | 서버 없이 호스팅하는 정적 사이트 | 불요 |

`def main(argv)` — 위 플래그를 디스패치. ¹전체 권고서는 DB만 읽으면 동작.

## 판정 엔진 (`checks.py`) ★

등급(severity): `mechanical`🔧(번호이동 등 기계적 — 자동 수정안 후보) ·
`review`⚠️(내용 변경 의심) · `check`📋(삭제 의심 등 사람 판단) · `current`✅(현행 유지).
1차 신호는 **현행 조문의 `<개정/신설/전문개정 YYYY.M.D>` 태그** vs 조례 시행일.

```python
amend_dates(content) / latest_amend_date(content)        # <개정> 태그 날짜 추출
basis_dates(content, ord_enforce)                        # (당시기준, 현행기준, amended_after)
check_clause(articles, clause_label, ord_enforce, law_name="", law_id="")
    # → finding dict. 1단계: 조문 시행일·부재 기반 판정(현행이면 category=current)
diff_clause(old_arts, cur_arts, clause_label, ord_enforce, law_name="", law_id="",
            old_enforce="", subspec=None)
    # → 2단계: <개정> 태그를 1차 기준으로 변경 판정, 당시↔현행 diff 근거 첨부
extract_subunit(content, hang=None, ho=None, mok=None)   # 항/호/목 단위 추출
summarize(findings)                                      # severity 카운트 요약
```

## 설계 불변식 (확장 시 깨지 말아야 할 것)
- **stdlib-only**, 외부 의존성 0 / 외부 LLM·임베딩 없음 / 오프라인 우선.
- **단일 엔진·단일 SQLite**, 배치 1회 → 이후 DB-only 서빙.
- 데이터 소스는 `src` 덕타이핑 인터페이스로 교체(Live/DB/StaleAware) — 분석 코드는 동일.
- 수집/분석 명령 분리는 기각(분석 산출물이 수집 시점에 필요 → 이중분석).
- 현재 판정은 "인용 조항이 개정·삭제됐는가"라는 **시점·존재 신호** 위주.
  내용적 충돌("위임 범위 일탈")은 **미구현 — 가장 유망한 미개척 지점**.
