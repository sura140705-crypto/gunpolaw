# 조례 정비 시스템 — 시스템 설계 (권위본)

작성 2026-06-26. 이 문서가 **권위 설계서**다. `효율성_분석.md`(진단)·`통합뷰_설계.md`(UI 스케치)는 배경 참고. 그린필드 승인됨 — 기존 코드/DB/UI는 더 깔끔한 쪽이면 폐기.

## 1. 목적·사용자·원칙
- **목적**: 상위법 개정에 따른 조례 **단순 정비를 일괄 발굴**해, 총괄담당자가 과별로 갈라 통지 → 부서가 세부 개정. 실제 업무 활용 + 사례 발표.
- **사용자**: **총괄담당자 1부류**. 개별담당자는 사용자가 아님(과별 리포트를 통지받아 시스템 밖 작업).
- **재사용**: 타 시군은 `org/sborg/지자체명` 설정만 교체.
- **핵심 원칙**: **배치 1회로 모든 자료를 DB에 적재 → UI는 DB만 읽는다(라이브 API 호출 0).** 데이터는 배치 시점 **스냅샷** + **기준일 stamp**. 신선도는 **정기 재배치**(월1회 정기 + 수동)로 확보. 인용된 법령만 저장(전체 법령DB 아님).

## 2. 두 모드
```
[BATCH] (무겁다, 정기 1회)            [SERVE] (가볍다, 상시)
 법제처 OpenAPI ──받아서──► gunpolaw.db ──읽기전용──► 총괄 UI
 수집·추출·법령적재·판정 전부 저장        (라이브 API 0)   전체/과별 뷰·과별 리포트 내보내기
```

## 3. 데이터 모델 (단일 gunpolaw.db, 최종)
- **batch_meta**(id, org, sborg, 지자체명, batch_date, 조례수, 법령수, 상태) — 스냅샷 기준일·재사용 설정.
- **ordinances**(mst PK, lid, name, knd, **dept 담당과**, promulg_date, enforce_date, **body_xml**, fetched_at) — 본문·담당과 포함(legacy DB 흡수).
- **ord_law_links**(mst, law_id, law_name) — lnkOrg 공식 연계.
- **laws**(law_id PK, name, current_mst, enforce_date, body_xml, fetched_at) — 인용된 법령 **현행 본문 영속**.
- **law_articles**(law_id, label, jo, ga, title, enforce_date, amend_dates, moved_from/to, content, PK(law_id,label)) — 파싱 조문(호 포함). UI 조문 팝업·diff가 여기서.
- **law_versions**(law_id, version_mst, enforce_date, body_xml, PK(law_id,version_mst)) — deep '당시 시행본' 본문 영속.
- **citations**(id, mst, ord_article 조례조문, law_id, law_name, clause_label, **span_start/end**, naked, ord_seq) — 인용+위치. UI 하이라이트가 여기서(라이브 추출 불요).
- **findings**(… 현행 컬럼 + cite_naked …) — 변경 판정·권고. 등급=일괄/개별 분류축.

→ STEP1 검색·STEP2 하이라이트·조문 팝업·STEP3 권고·과별 리포트가 **전부 이 DB에서**.

## 4. BATCH 파이프라인 (self-contained)
1. **수집**: 목록(ordin) 전건 → ordinances(+dept) 적재. lnkOrg → ord_law_links.
2. **인용 추출**(엔진 1개, gunpolaw.extract): 조문별 인용 + **span** + 맨몸 인식 → citations 적재.
3. **법령 적재**(캐시): 인용된 법령ID별로 현행 본문 **1회** 받아 laws/law_articles 저장(이미 있으면 skip).
4. **deep 당시본**(필요분만): 조례 시행일에 끼는 버전을 law_versions에 저장. 판정 자체는 현행본 개정태그로 하되 `[당시]` diff 표시용.
5. **판정**(checks): citations × 법령조문 → findings 적재(등급·cite_naked·기준일).
6. **stamp**: batch_meta에 batch_date·집계 기록.
- 전체 재배치(증분 X)로 단순. "오래 걸려도 OK". (증분은 후속 최적화: law_id별 최신 시행일 비교 후 변경분만 재적재.)

## 5. SERVE (읽기전용, 라이브 0)
- `/api/overview` : batch_meta + 등급별·**담당과별** 집계(총괄 대시보드).
- `/api/ordinances?dept=` : 담당과 필터 조회.
- `/api/ordinance/{mst}` : 본문 + citations(span) + findings 조인(통합 뷰용).
- `/api/dept_report?dept=` : 과별 개정 지시서(HTML/PDF·CSV) — 통지용 산출물.
- 전부 SELECT만. OC 키 불요(배치만 키 필요).

## 6. UI (총괄 1화면)
- **대시보드**: 스냅샷 기준일 배너 / 등급 카드(🔧📐⚠️📋✅) / **담당과별 표**(과 · 정비건수 · 등급분포 · [과별 리포트]).
- **담당과 드롭다운 필터**(무인증): 전체 ↔ 특정 과. '총괄/세부 구분해 보기'를 이 필터로 충족.
- **조례 상세(통합)**: 좌=본문+인용 하이라이트(파랑「」/보라 맨몸), 우=인용별 권고(등급·「」누락·당시/현행 diff·기준일). 좌우 상호 포커스. (= 통합뷰_설계 STEP2+3)
- **과별 리포트 내보내기**: 그 과 조례들의 권고를 묶은 인쇄/PDF·CSV.

## 7. 폐기 대상 (그린필드)
- `phase6.py`(라이브 검증·중복 파싱/토큰화) — 삭제.
- `file1.py`의 추출·검증·check_freshness — 삭제. 남길 건 HTTP 서버 골격뿐이거나, gunpolaw에 얇은 serve 모듈 신설로 대체.
- `gunpo_ordinances.db` — dept·body를 gunpolaw.db로 흡수 후 폐기.
- `gunpo_ui_v2.html` — 총괄 단일 UI로 교체(또는 대폭 축소).
- 라이브 엔드포인트(check_clause*, old_and_new 등) — 삭제.

## 8. 재사용(타 시군)
- 설정 1곳(org/sborg/지자체명) → batch가 그 지자체 조례·연계로 동작. 코드 변경 0.

## 9. 이행 단계 (각 단계 한글 커밋·검증)
1. **DB 스키마 확정 + 법령/버전/citations/dept 적재**(배치 self-contained화). 죽은 테이블 활성화. ← **먼저, 가치·저위험**.
2. **추출 엔진에 span 추가** → citations 적재 → 하이라이트 DB서빙.
3. **serve 모듈**(읽기전용 엔드포인트) + 총괄 대시보드·담당과 필터.
4. **조례 상세 통합 뷰**(하이라이트↔권고).
5. **과별 리포트 내보내기**.
6. **레거시 폐기**(phase6/file1 추출·검증/gunpo_ordinances.db/구 UI).
