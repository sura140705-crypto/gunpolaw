# STEP2+STEP3 통합 뷰 설계 (초안)

작성 2026-06-26. 상태: **설계 합의 대기** (구현 전). 결정이 필요한 항목은 §6.

## 1. 배경 / 목표
- 사용자 관찰: STEP2(인용 하이라이트)와 STEP3(개정 권고)를 **따로 둘 이유가 없다 → 한 화면에서 동시에**.
- 추가 관찰: 방금 STEP3에 넣은 **맨몸(「」 없는) 인용 인식**이 STEP1/STEP2 하이라이트엔 반영 안 됨.
- 한 줄 목표: **"조례 본문의 인용을 색칠(맨몸 포함)하고, 인용을 고르면 그 자리에서 '이걸 이렇게 고쳐라' 권고가 뜨는" 단일 화면.**

## 2. 현재 구조 진단 — 추출 엔진이 두 벌
| | STEP1·STEP2 | STEP3(권고) |
|---|---|---|
| 추출 | `file1.py` `ref_spans_for_articles`/`extract_all_refs` | `gunpolaw/extract.py` |
| 산출 | 문자 **span**(start/end) — 하이라이트용. 변경탐지·맨몸 인식 없음 | ref(법명·조라벨·ord_article·**naked**) + 사전배치 findings(변경탐지) |
| 「」 없는 인용 | 못 잡음(LAW_CITE_RE 「」 필수) | 인식함(NAKED_LAW_RE) |

→ 같은 일을 하는 코드가 두 군데. 하이라이트(span)는 file1.py만, 분석(변경탐지·naked)은 gunpolaw만 가지고 있어 **합치려면 한쪽으로 일원화**가 선행돼야 한다.

## 3. 통합 뷰 레이아웃 — 기존 STEP2 `split-grid` 재사용
```
┌ STEP2(분석·권고) ─────────────────────────────────────────────┐

│ ┌── 좌: 조례 원문(1.4fr) ───────┐ ┌── 우: 인스펙터/권고(1fr, sticky)┐│
│ │ 제1조(목적) 이 조례는          │ │ ▸ 선택한 인용                  ││
│ │   〔주민등록법〕 제2조제2항…    │ │  「주민등록법」 제2조           ││

│ └───────────────────────────────┘ └────────────────────────────────┘│
```

- 좌측: 조문 본문 + 인용 span 하이라이트. 색: 파랑=「」법령, **보라=맨몸**, 보라약=자치법규.
- 우측(sticky): 고른 인용의 **권고 카드**(report.py와 동일 내용: 등급배지·「」누락·행동지시·기준일·당시/현행 diff). 아무것도 안 고르면 조례 전체 권고 목록.
- **상호 하이라이트**: 좌측 span 클릭 → 우측 해당 카드로 스크롤·강조 / 우측 카드 클릭 → 좌측 span 깜빡.

## 4. 엔진 일원화 방안 (권장) — `gunpolaw.extract`에 span 추가
- 지금 `_extract_segments`는 이미 조문별 `finditer`라 `m.start()/m.end()`를 알고 있음 → `_ref()`에 `span`(조문 내 offset)·`ord_article` 저장만 추가하면 **하이라이트용 span을 gunpolaw가 그대로 산출**.
- 신규 `citation_spans(articles)` → `{조문no: [{start,end,kind,law_name,clause_label,naked}...]}` (file1.py 출력과 호환 형태, 단 **naked 플래그 포함**).
- STEP1/STEP2 하이라이트가 이걸 쓰면 → **맨몸 인용도 자동으로 하이라이트**(Q1 해소) + file1.py의 중복 추출기 제거.
- 권고(우측)는 **사전배치 findings**(`recommend_fragment`) 그대로 사용.

### 데이터 조인 (span ↔ finding)
- 키: **(ord_article 조례조문, law_name, clause_label)**. 예) span(제1조, 주민등록법, 제2조) ↔ finding(ord_clause=제1조, law_name=주민등록법, clause_label=제2조).
- 법명만 인용(조항 없음)은 (ord_article, law_name) ↔ finding(law_articles). 같은 법 다중 인용은 `ord_seq`로 보조 정렬.
- 매칭 안 되는 span(현행유지라 finding 없음) → 우측 "✅ 현행 정합" 표기.

## 5. 엣지/주의
- **라이브 vs 배치**: 하이라이트=라이브 추출(즉석), 권고=사전배치. 미배치 조례는 우측 "권고 데이터 없음 — 배치 필요". 군포는 전건 배치 OK.
- file1.py 추출기 교체는 **STEP1 상세 모달**에도 영향(같은 함수). 일원화하면 STEP1도 맨몸 인식 이득. 단 회귀 위험 → 교체 시 기존 「」 케이스 스냅샷 비교 필요.
- gunpolaw.extract는 `body`(조내용)만 봄 — file1.py ref_spans는 `is_article` 등 메타 사용. span 산출 시 조문 인덱스/메타 매핑 유지 필요.
- 호(號) 단위 본문 미포함(파서 한계)은 별건(이미 백로그).

## 6. 결정 필요 (사용자)
1. **엔진 일원화 범위**: (a) gunpolaw로 일원화하고 file1.py 추출기 제거[권장] / (b) file1.py에 맨몸패턴만 이식(중복 유지, 저위험).
2. **STEP 구성**: STEP2를 '분석·권고' 단일 패널로 만들고 STEP3 패널 흡수 / 아니면 STEP3는 '전체 권고서(인쇄용)'로 남기고 STEP2에 인용별 권고만 인라인.
3. **우측 기본 표시**: 인용 클릭 전 기본값 = 조례 전체 권고 목록 / 빈 안내.
4. **레거시 실시간 검증(phase6 check)**: 통합 뷰에선 제거 / `<details>`로 보존.

## 7. 단계별 구현 계획 (합의 후)
- 1단계: `gunpolaw.extract`에 span/`citation_spans` 추가 + 단위테스트(맨몸 span 포함).
- 2단계: `file1.py` `/api/detail`·`/api/extract_refs` 하이라이트를 `citation_spans`로 교체(STEP1/2 맨몸 하이라이트 확보). 기존 「」 회귀 스냅샷 확인.
- 3단계: `/api/recommend`(이미 있음)와 span을 조인하는 `/api/analyze2`(또는 클라이언트 조인) → 통합 뷰 렌더(좌 하이라이트 ↔ 우 권고 카드 상호 포커스).
- 4단계: STEP3 패널 정리(전체 권고서 인쇄 뷰만 남김), 네비 라벨 재정리.
