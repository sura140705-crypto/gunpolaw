# 자치법규 정비 대시보드 — 디자인 보완 전달 자료

다른 AI에게 이 웹페이지의 **디자인 보완**을 맡기기 위한 자료입니다. 아래 순서로 정리했습니다.

---

## 0. 먼저 읽어주세요 — 필수 제약 (디자인 시 지켜야 함)

이 페이지는 일반 웹앱과 배포 방식이 다릅니다. **디자인을 바꾸되 아래는 반드시 지켜주세요.**

- **순수 바닐라 HTML/CSS/JS만.** React·Vue·Tailwind·Bootstrap·jQuery 등 **프레임워크/빌드 도구 사용 금지.**
- **외부 CDN·웹폰트·아이콘 라이브러리 로드 금지.** 오프라인 환경·정적 사이트로 배포되므로 네트워크 의존이 있으면 깨집니다. (현재 이모지(⚠️📋🔧🏠)를 아이콘 대용으로 씀 — 유지 권장)
- **단일 파일 구조 유지.** 전체가 하나의 HTML 문자열(`<style>` + `<body>` + `<script>`)로 서빙됩니다. CSS/JS 분리 파일 추가 불가.
- **클라이언트 렌더링.** 서버 템플릿 없음. HTML은 빈 컨테이너만 있고, JS가 `fetch('/api/*.json')`으로 데이터를 받아 DOM을 그립니다. `STATIC` 플래그가 true면 서버 없이 정적 JSON 파일을 읽습니다(정적 배포).
- **색/등급 체계 유지** (아래 4-2 참조). 담당자들이 이미 익숙한 색 코드입니다.

즉, **CSS 스타일링·레이아웃·타이포·간격·반응형 개선**은 환영하지만, **기술 스택 교체는 불가**합니다.

---

## 1. 전체 HTML 소스

- 같은 폴더의 **`dashboard.html`** 이 전문입니다(약 34KB, `<style>`+`<body>`+`<script>` 포함).
- 원본은 Python 파일 `gunpolaw/serve.py` 안의 `DASHBOARD_HTML` 문자열입니다. 디자인 결과는 이 문자열로 다시 반영됩니다.

## 2. CSS 전문

- **별도 CSS 파일 없음.** `dashboard.html`의 `<head><style> … </style></head>` 블록이 CSS 전문입니다.
- CSS 변수(색): `--mech`(기계적) `--rev`(실질검토) `--chk`(확인) `--fmt`(서식) `--cur`(현행) 등이 `:root`에 정의돼 있습니다.
- 반응형 분기점: **`@media (max-width:760px)`** — 이 이하를 모바일로 취급.

## 3. 페이지 구조 (배치 순서)

```
헤더(h1 "자치법규 정비 — 총괄 대시보드", 우측 '판정 근거 검사' 링크)
  └ 배너(#banner): 지자체명 · 스냅샷 기준일 · 조례/법령/판정 건수
요약 히어로(#hero)
  ├ 대형 숫자: 정비 필요 조례 건수(예: 257)
  ├ 진행바: 전체 대비 비율
  └ 등급 칩: ⚠️실질검토 581 · 📋확인 47 · 📐서식 49 …(건수는 finding 단위)
법령 개정 알림(#changes, 접이식): 상위법 개정 → 영향 조례 역추적(있을 때만)
컨트롤 바(.controls): [🏠 첫페이지] [🔍 검색창] [담당과 드롭다운] [정비 대상만 ☑] [현재 위치 crumb]
메인 목록(#listPanel) — 상태에 따라 셋 중 하나:
  (A) 소관업무별 편 아코디언(기본)  — 제01편 의회 … 제12편, 편 클릭 시 하위 과 펼침
  (B) 조례 목록 카드              — 특정 과 선택 시
  (C) 조례 상세(#detailPanel)     — 조례 클릭 시(목록 숨김)
       └ 좌: 조례 본문(인용 하이라이트) | 우: 조문별 검토 사항
          (모바일에선 세로 스택 + [본문]/[검토] 탭 전환)
```

**현재 화면 상태(state) 변수**: `curDept`(선택 과) · `curQuery`(검색어) · `curMst`(열린 조례). 셋 다 비면 (A) 편 아코디언이 홈 화면.

**데스크톱 vs 모바일 의도**: 데스크톱은 총괄 관리자용이라 **정보 밀도 높게**(편 등급칩 노출 등), 모바일은 **간단·터치 위주**. 이 차등을 더 살려주면 좋습니다.

## 4. 핵심 기능 — 이 페이지가 보여주려는 것

### 4-1. 목적
군포시 **자치법규(조례·규칙)가 인용한 상위 법령·행정규칙 조항이, 그 조례 시행 이후 개정·삭제됐는지**를 조문 단위로 자동 판정해, **정비가 필요한 조례·조문을 담당 부서(과)별로 보여주는** 읽기전용 관리 대시보드입니다. 사용자는 **법무 총괄 관리자 1인**(주 1회 점검).

즉 화면이 답하는 질문: *"어느 조례의 어느 조문이, 인용한 상위법이 바뀌어서 손봐야 하는가?"*

### 4-2. 판정 등급(severity) — 색/의미의 핵심
| 등급 | 표시 | 의미 |
|---|---|---|
| mechanical | 🔧 기계적 개정 | 조문번호 이동 등 — 인용 번호만 정정 |
| review | ⚠️ 실질 검토 | 내용 변경·삭제 의심 — 사람이 검토·정비 |
| check | 📋 확인 | 소재 미확인·미해결 — 사람 확인 |
| format | 📐 서식 정비 | 내용은 현행이나 「」 누락 등 서식 결함 |
| current | ✅ 현행 유지 | 변경 없음(집계에만) |

### 4-3. 표출 흐름
소관업무(편) → 담당과 → 조례 → **조례 조문별 검토 항목**(좌측 본문 인용을 클릭하면 우측 해당 검토가 펼쳐지고, 당시↔현행 조문 **diff**가 근거로 표시됨).

## 5. 데이터 예시 (실제 화면에 들어가는 값)

전체는 같은 폴더 `sample_overview.json`(요약·소관 집계), `sample_ordinance_detail.json`(조례 1건 상세: 본문·인용 하이라이트·검토) 참고. 아래는 대표 2건.

### 예시 1 — 내용변경(⚠️ 실질검토), 당시↔현행 diff
- **조례**: 군포시 보훈회관 설치·운영 조례 (시행 2020-05-11)
- **인용**: 「국가유공자 등 예우 및 지원에 관한 법률」 **제4조** → 조례 **제2조**에서 인용
- **판정**: `review / 내용변경` — "제4조가 조례 시행(2020-05-11) 이후 개정됨(개정 2020-03-24→2023-03-04) — 검토 필요"
- **근거(당시 조문 텍스트)**: "제4조(적용 대상 국가유공자) ① 다음 각 호의 어느 하나에 해당하는 국가유공자, 그 유족 또는 가족 … 은 이 법에 따른 예우를 받는다."
- 화면에선 **당시 vs 현행** 텍스트를 토큰 단위로 비교해 바뀐 부분을 `<mark>`로 강조.

### 예시 2 — 정의 조항 개정(⚠️ 실질검토)
- **조례**: 군포시 감염병 예방 및 관리에 관한 조례 (시행 2020-09-29)
- **인용**: 「감염병의 예방 및 관리에 관한 법률」 **제2조(정의)** → 조례 제2조
- **판정**: `review / 내용변경` — "제2조가 조례 시행 이후 개정됨(개정 2020-08-11→2023-08-08) — 검토 필요"
- **근거**: "제2조(정의) 이 법에서 사용하는 용어의 뜻은 다음과 같다. <개정 2010.1.18, … 2019.12.3, …>"

### 요약 데이터(overview) 형태
```json
{
  "totals": { "ordinances": 640, "action": 257, "depts": 36 },
  "grades": { "mechanical": 0, "review": 581, "check": 47, "format": 49, "current": 2541 },
  "dept_groups": [
    { "no": "01", "name": "의회", "action": 16, "total": 39,
      "grades": {…}, "depts": [ { "dept": "의회사무과", "action": 16, "total": 39, "grades": {…} } ] },
    { "no": "05", "name": "행정지원국", "action": 45, "total": 147, "depts": [ … 6개 과 … ] }
    // … 제01편 의회 ~ 제12편 하부행정기관 (군포시 행정조직 순서)
  ]
}
```
(숫자는 스냅샷 시점 값 — 실제 파일 `sample_overview.json` 참조)

## 6. 사용 중인 라이브러리 / 프레임워크

- **프런트엔드**: 순수 **바닐라 HTML + CSS + JavaScript(ES6)**. 프레임워크·번들러·전처리기·외부 CDN **전무**.
- **데이터 연동**: `fetch()`로 자체 JSON API(`/api/overview`, `/api/ordinances`, `/api/ordinance/<id>`, `/api/changes`) 호출 → JS가 템플릿 문자열로 DOM 생성.
- **서버**: Python 3 **표준 라이브러리 `http.server`**(외부 의존성 0). 대시보드 HTML은 서버가 문자열로 통째 반환.
- **정적 배포 모드**: 같은 HTML을 서버 없이 정적 파일로도 배포(JS의 `STATIC` 플래그가 API 경로를 정적 JSON 파일 경로로 치환).
- 아이콘/그래픽: **유니코드 이모지**만 사용(외부 아이콘 폰트 없음).

## 부탁하고 싶은 디자인 방향 (참고)
- 총괄 관리자가 "정비 필요한 것"을 **빠르게 우선순위 파악** → **해당 조문으로 드릴다운**하는 흐름을 더 명확하게.
- 데스크톱은 정보 밀도 높게(한 화면에 현황 파악), 모바일은 단순·터치 친화.
- 등급 색 체계·이모지·단일 파일·오프라인 제약은 유지.
- 좌(조례 본문)↔우(검토·diff) 연동 상세 화면의 가독성 개선 여지가 큼.
